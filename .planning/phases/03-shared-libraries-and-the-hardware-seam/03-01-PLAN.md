  <action>
Create three PlatformIO libraries under `shared/lib/`, in the default layout, with no `build` section in any manifest — a custom source directory is the cause of the silently-dropped-translation-unit trap, not its fix.

**`shared/lib/emb_hal`** — the seam, framework-free, interface only, so `include/` and no `src/`. Its manifest declares exactly two keys: the name `emb_hal` and the version `0.1.0`. Its header `include/emb_hal.h` is pure C, guarded by an include guard and by a C++ guard around the declarations, and declares four functions: `bool emb_hal_console_ready(void)`, `void emb_hal_init(void)`, `void emb_hal_write_line(const char *line)` and `unsigned long emb_hal_millis(void)`. State in the header comment the two contract facts a reader cannot infer: the write function terminates the line itself, so a caller passes text without a newline; and the readiness predicate is false before initialisation and remains false if the console never came up. Declare no pin, no UART number and no bridge identity anywhere in this file — that is what keeps the folded parameterization obligation honoured on the library side. Write a rationale-first file comment naming what the file is for and why the shape is what it is.

**`shared/lib/emb_hal_arduino`** — the single framework-touching unit in the shared tree, so `src/` and deliberately **no** `include/`: a backend must expose no public header, and the directory split makes that boundary structural rather than conventional. Its manifest declares the name `emb_hal_arduino`, the version `0.1.0` and the framework declaration `["arduino"]` — the last as a plain correctness statement, measured harmless, and explicitly not as the exemption mechanism. Its source `src/emb_hal_arduino.c` is C, includes the core's C-callable UART header and the core's C-callable clock header, keeps a file-static UART handle, and implements the seam's four functions: readiness as a non-null handle, `emb_hal_millis` forwarding to the core's millisecond clock, and the write function emitting the caller's bytes through the core's buffered UART write then a single newline through the core's single-byte write. Initialise with the argument list the research recorded, passing the literal `0` as the UART number because the framework's serial-number macro lives in the C++ header this file must not include. Record in the file comment why the C++ console object is unusable here and that this file is the only one allowed to see the framework. If that argument list does not survive the compiler, adjust only the arguments and keep the shape.

**`shared/lib/emb_log`** — pure logic, framework-free, `include/` plus `src/`. Its manifest declares `emb_log` at version `0.1.0`. Its header `include/emb_log.h` is pure C with the same two guards, defines `EMB_LOG_LINE_MAX` as 96, and declares `void emb_log_init(void)`, `bool emb_log_ready(void)` and `bool emb_log_line(const char *text)`. Document the line contract in the header: a written line begins with the module's own tag, then a colon and a space, then the caller's text — and carries no trailing newline, because the seam terminates it. Its source `src/emb_log.c` includes its own header and the seam header, and nothing else. Own the tag as a file-static string literal **in the source, not in the header**, so a later edit to it recompiles one translation unit rather than every consumer. Implement initialisation by calling the seam's initialiser; implement readiness by forwarding the seam's readiness predicate; implement the line write by composing the tag, a colon and a space, and the caller's text into a bounded stack buffer, refusing — by returning false and writing nothing — when the text does not fit or the sink is not ready.

**The not-ready-sink decision, recorded rather than discovered** (`D-06`, ASVS V7): a write against a not-ready sink is **dropped, reported as false, and never buffered and never replaced with a diagnostic**. Buffering would make the failure invisible until a later flush; substituting a diagnostic would put text on a channel that is known not to carry it. The readiness predicate is the caller's way to distinguish the two, and it is the shim that decides what to print.

Then rewire the consumer. Add to `homeworks/project-baseline/platformio.ini`, inside the environment section that already exists, exactly one `lib_deps` key on **one comma-separated line** carrying three specs in this order — `emb_hal`, `emb_hal_arduino`, `emb_log` — each written as the library name, an equals sign, and the relative path form the README already documents. One entry per library is required including the transitive one: the dependency scanner does not read a library's own source, so an include that exists only inside another library fails at compile with a missing-header error that names the header rather than the missing line. The comma form is not cosmetic; the multi-line form is mis-read by this repository's own configuration reader. Do not move these lines into the shared fragment — it would give every homework all three libraries and hide the consumer's dependency list from a search. Do not add anything else to this file.

Then rewrite `homeworks/project-baseline/src/main.cpp` as a thin C++ shim. It keeps the framework-mandated entry-point signatures because the core declares them without a C-linkage guard, so a C definition would emit an unmangled name the core never looks for. It includes the framework header for that linkage reason, includes the core's standard-input/output header for formatting, and includes the pure-logic module's header directly — the seam's guard makes that legal from C++. `setup()` calls the pure-logic module's initialiser, formats the same three readings the file reports today (flash size, the PSRAM-found flag, the PSRAM size) into a local buffer, and hands that text to the pure-logic module's line writer. `loop()` stays empty. Add nothing else: no GPIO, no delay, no second line. Keep the existing header comments' claims true, and extend them to note that everything below the shim is C.

Do not write any host test either — a test committed now would be a file maintained without ever having run (`D-12`).
