<objective>
Close the two repository-wide rules this phase inherits and correct the roadmap where the measurement disagrees with it.

**MVP user story (verbatim from `ROADMAP.md` § Phase 3):** **As a** course student maintaining one public coursework repository, **I want to** consume reusable modules as real PlatformIO libraries through live symlinked dependencies, with no framework include above a narrow HAL seam, **so that** pure logic is testable on the host and the later ESP-IDF migration is a backend swap rather than a rewrite.

Purpose: two of this phase's five success criteria are about the *mechanism* rather than about a file — that nothing in the repository still reaches shared code through the deprecated global-library directives, and that the one-level depth rule now fails for real because a homework finally declares a symlinked dependency. Neither can be discharged by writing code; both are discharged by taking a reading and recording it. The depth rule is the more important of the two: `ROADMAP.md` currently asserts a failure mode that the committed tree does not produce, and Phase 1's accepted override retires on a trigger that this phase fires. Leaving either statement standing would put a claim into the repository that a later reader could disprove in one command.

**Requirement mapping.** Criteria 4 and 5 carry no requirement ID of their own; they are the mechanism-level discharge of `SHARED-02`'s declaration — the depth arithmetic *is* the resolution semantics of the dependency line, and the deprecated-directive scan is what keeps the live-path form the only way shared code is consumed.

Output: the scan in `tools/tests/check-hal-seam.test.mjs`; the three depth-measurement arms in `03-03-SUMMARY.md`; and the dated corrections in `.planning/ROADMAP.md`.

**Not in this plan, and not claimed here:** any hook or CI wiring of the scan (Phase 6, `VERIFY-02`); `shared/hardware/`, the pin database and every board fact (Phase 4, `HW-02`/`HW-03`); the ESP-IDF backend; `[env:native]` and the host test suite (Phase 5).
</objective>
