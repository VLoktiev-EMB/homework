<objective>
Give the seam a guard that cannot be argued with: a repository-owned check that walks the shared library tree, names every framework include it finds with file and line, exits non-zero on the first tree that carries one, refuses a tree that holds no library at all, and skips exactly one named directory. Then give that check a regression suite whose every assertion is falsifiable, and extend the shared fixture builder the existing suites already use rather than forking it.

**MVP user story (verbatim from `ROADMAP.md` § Phase 3):** **As a** course student maintaining one public coursework repository, **I want to** consume reusable modules as real PlatformIO libraries through live symlinked dependencies, with no framework include above a narrow HAL seam, **so that** pure logic is testable on the host and the later ESP-IDF migration is a backend swap rather than a rewrite.

Purpose: this plan is the reason the seam survives contact with later phases. `SHARED-03` states a property the shared tree must hold; nothing holds it except a check that reads the tree and refuses. The check is the third slice of this phase and it is deliberately built on the tree plan 03-01 produced, because a scanner proven on fixtures alone proves nothing about the tree it guards — and because the empty-tree case is not hypothetical: an empty shared directory is exactly what this repository looked like before this phase, so the check's very first execution against the real tree has to be correct.

Output: `tools/check-hal-seam.mjs`; `tools/tests/check-hal-seam.test.mjs`; the two additions to `tools/tests/helpers.mjs`; and `03-02-SUMMARY.md`.

**Not in this plan, and not claimed here:** wiring the check into any hook or CI job (Phase 6, `VERIFY-02`) — this plan delivers the script and its test and says so; the repository-wide scan for the deprecated global-library directives and the depth-rule measurement (plan 03-03); the ROADMAP corrections (plan 03-03); `[env:native]` and any host test suite (Phase 5).
</objective>

Write `tools/check-hal-seam.mjs` as a repository-owned script in the shape the two existing tools establish: an executable Node module, standard library only, its scan root derived from its own file location so it works from any working directory, a top block comment stating what it enforces and why the shape is what it is, and an entry-point guard so it can be imported by its own test without its command-line work running.

Its argument surface is one flag: `--root <dir>` replaces the scanned tree. A missing value after the flag exits 2 with a message naming the required form, and any other argument exits 2 rather than being ignored — a mistyped flag that silently scans the repository is exactly the class of quiet mistake the check exists to remove.

The scan walks the shared library directory. Enumerate its immediate subdirectories through the same `isDirectory()`-based helper the discovery module uses, because that predicate is false for a symlink and therefore doubles as the escape control; a plain file beside the libraries is not a library. Skip the single exempt directory by exact name at that first level only. If no library directory remains, exit 1 with a message naming the scanned directory and saying in words that a gate which checked nothing must not exit zero.

For every remaining library, walk every regular file beneath it — **no extension filter**. An extension allow-list is a second place a newly introduced file type can be silently missed, and the include pattern is anchored, so a file that is not source simply never matches. The anchored pattern captures the include path out of both the angled and the quoted form. A captured path is a framework include when: its trailing name equals the framework's own core header exactly; or it begins with the platform's own header prefix; or it begins with the Arduino HAL prefix, which the first prefix does not cover because those headers begin with the chip name and an underscore-free hyphen; or it begins with the real-time operating system's directory; or it begins with the peripheral driver's directory.

Collect each hit as its repository-relative path, its one-based line number, and the include path, then **sort by path and then by line** before printing, so the report does not depend on the directory order the filesystem returns. Print one line per hit in a form that names the file, the line and the include; exit 1 when there is at least one hit. When there are none, print one line naming how many libraries were scanned and that no framework include was found, and exit 0 — the count is what separates "found nothing" from "scanned nothing".

Then extend `tools/tests/helpers.mjs`, beside the fragment-consumer builder and following its idiom, with a shared-library fixture builder and a spawn wrapper. The builder takes a fixture root, an optional list of library names defaulting to the three the repository ships, and options that make each assertion falsifiable: omit the version key in a named library's manifest; give a named library's manifest a name that is not its directory's; omit a named library's manifest entirely; plant an include line of a chosen form in a chosen library's source; and rename the backend directory to a near-miss of the exempt name. It writes a manifest, an interface header and a source file per library, returns the root and the per-library manifest paths, and registers the tree with the cleanup list. The spawn wrapper runs the repository's real script against a fixture root with the working directory set to the checkout that owns it, so the script under test derives nothing from where it happens to run. Export the check's absolute path and the default library list alongside, exactly as the sweep's path is exported today.

Then write the first test in `tools/tests/check-hal-seam.test.mjs`: build a fixture library tree, plant one framework include of the core-header form in a library that is not the exempt one, spawn the check against the fixture, and assert that it exits non-zero and that its output names both the file it was planted in and the include. Extend the suite so every class of framework include the check must catch is planted in its own fixture and asserted, and one class it must not catch is asserted quiet. Take a reading per case against a throwaway tree; add nothing to the repository tree itself.

The classes to plant, each in a library that is not the exempt one, each asserted to be named in the output with its file and line and to make the check exit non-zero: the framework's own core header in the angled form; the same in the quoted form, because the include pattern accepts both and a scanner that accepts one is a scanner with a hole; the platform's own header prefix, which is the class the roadmap's literal wording misses; the Arduino HAL prefix, which begins with the chip name rather than the platform prefix and which the platform prefix therefore does not cover; the real-time operating system's directory; and the peripheral driver's directory. Then exercise both edges of the exemption, which is the part of the check most likely to be quietly wrong. Positive: the same Arduino HAL include planted inside the exempt backend directory is passed over and the check exits zero. Negative, and this one is the assertion's reason to exist: rename the backend directory to a name that merely resembles the exempt one, plant the same include, and assert the check now **names** it. An exemption keyed to a pattern would pass the first case and fail this one, which is precisely why the list is a list.

Then exercise the empty edge. Build a fixture whose shared library directory exists but holds no library — no directory with a manifest, only a plain file such as a README — and assert the check exits non-zero and prints a message naming the directory it scanned and the library count. Then build a fixture where the shared library directory is absent entirely and assert the same refusal, so the missing-directory case cannot fall through as a crash with an unrelated message.

Then exercise determinism. Plant two includes in two different files of the same fixture, run the check twice, and assert both runs printed byte-identical output, and that the order of the reported lines is the order obtained by sorting the expected pairs by path and then line. State in the test's comment what this does and does not prove: it proves the report is stable and sorted, and it cannot force the filesystem to return an unstable directory order, so the sorted assertion is the part that carries the weight.

Do not weaken the check to make a case pass. If a planted class is not reported, the finding that the check misses it is the result to record — the case is not the thing to adjust. Do not add a case that asserts only that the script exits — every assertion names the file or the include it expects to see.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the shared library tree → the check's verdict | The check reads untrusted content — any file under the shared tree — and turns it into a pass or a fail. Every path it reports becomes repository-relative output a human reads. |
| the check → the seam's integrity | A false negative here is silent and permanent: the framework include compiles, the seam is gone, and nothing downstream notices until the framework era changes. |
| the exemption list → the boundary it expresses | One line, one entry, and the one keystroke that widens the hole the check exists to close. |
| a fixture tree → the tracked tree | Every case in this plan builds a tree under the temporary directory; a leak into `shared/lib/` would be read as a real library by the check itself. |
| the consumer's configuration → the installed package name | The left-hand side of a dependency spec overrides the installed folder name while the dependency scanner reads the manifest, so a mismatch yields two names for one library. |
