**`.editorconfig`** — reproduce `01-RESEARCH.md` lines 847-880. Use **only the nine properties the EditorConfig specification defines**: indent style, indent size, tab width, end of line, charset, spelling language, trim trailing whitespace, insert final newline, and the root marker. The specification requires cores to accept syntactically valid unknown keys and requires plugins to **ignore** them, so an unknown key fails silently by design — a rule that appears to be owned and is inert.

Consequences that must hold:
- The root marker sits at the top of the file, outside any section.
- The universal section sets UTF-8, LF line endings, a final newline, trailing-whitespace trimming, space indentation at four columns.
- The Markdown and Markdown-variant section sets a two-column indent **and disables trailing-whitespace trimming**, with a comment recording why: two trailing spaces are a Markdown hard line break, so the universal rule is deliberately inverted in exactly this one place.
- The JSON/JSONC/YAML/INI/config/properties section uses a two-column indent.
- The C-family section uses a four-column indent.
- The shell section uses a two-column indent.
- The Makefile section switches to tab indentation.
- **Do not add a column-limit key and do not add a key that strips final newlines.** Both names look canonical because editor ecosystems and VS Code expose similar ones, but neither is an EditorConfig property; the abandoned scaffold declared both and both were inert. The column guide belongs to `.vscode/settings.json`'s ruler setting (task 3), which is what D-22 already says. Note the confusable pair so a reader does not "fix" the omission: the key that inserts a final newline **is** real and is used.
- Do not carry the abandoned scaffold's Python section (`git show origin/vl/init:.editorconfig`) — no Python source exists in the frozen tree.
