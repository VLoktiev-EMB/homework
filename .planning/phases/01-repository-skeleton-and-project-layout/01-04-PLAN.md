<objective>
Build the repo-wide gate that makes the folder-depth rule audible and makes an empty repository impossible to mistake for a green one — the sweep that discovers every homework, validates its name, enforces the one-level rule by name, and builds each project from the repository root while accumulating failures.

Purpose: this is where success criterion 2's second half is honestly discharged and criterion 4 is satisfied literally. It is also the mechanism Phase 6's CI matrix consumes, so its `--list` output and its validation order are contracts, not conveniences.
Output: `tools/sweep-homeworks.mjs`, `tools/tests/sweep.test.mjs`, and the extended fixture helper.

**Why the sweep is Node rather than shell — measured, not preferred:** `zsh -c 'for f in homeworks/*/platformio.ini; …'` prints `zsh:1: no matches found: homeworks/*/platformio.ini` and exits 1, aborting the script with a message that names no rule; POSIX `/bin/sh` with an existence guard lets the unmatched glob through and falls through to a zero exit — Pitfall 11 exactly. Neither default yields the required semantics. Node's directory read makes zero-match an explicit branch under this repository's control.
</objective>

- **The sweep tests must never run against the repository root.** A test that pointed the sweep at the real tree would build the real baseline and dirty `.pio/` in the act of testing the rule that says the tree stays clean. This is why the script takes a root override (below) and why every test builds its own `os.tmpdir()` fixture.
- **`node --test` semantics are measured, not assumed.** Bare `node --test` walks the whole tree and ran a test file found inside a homework folder; `node --test tools/` fails with `MODULE_NOT_FOUND`; the quoted glob `node --test "tools/**/*.test.mjs"` passes. The quoting is mandatory — unquoted, the shell expands it, and under zsh an unmatched glob is an error.
- **PlatformIO has no recursive command.** `pio run` accepts only `-e/-t/-d/-c`, verified from `--help`. A repo-wide build is necessarily an external loop that accumulates failures rather than stopping at the first.
- **`pio run -d` exit codes are measured:** `0` for a valid environment, `1` for a project with no environments or a non-PlatformIO directory, `2` for a path that does not exist.
- **`pio` is not on the interactive PATH on this machine and fails silently through a naive spawn.** With `pio` absent, a `spawnSync("pio", …, { stdio: "inherit" })` printed only the command banner and exited 1, with no error text at all, because the spawn error is a separate channel from the child's stderr. Branch on the spawn error separately from the child's exit status.

Its zero-match branch prints a reassuring line and falls through to a zero exit; its glob is the abandoned flat layout at the repository root; and it calls `pio` as a bare command. Create the single repo-wide gate. Read `01-RESEARCH.md` lines 576-650 for the verified implementation and reproduce its structure; read the negative analog first (`git show origin/vl/init:scripts/pio-build.sh`) to see the three failure modes it must not repeat.

**Shape.** A Node ES module with a shebang, importing `discoverHomeworks` and the printable id pattern from `./lib/discover.mjs`. No third-party dependency and no shell. Resolve the repository root from `import.meta.url` through `fileURLToPath` and `dirname` up one level, so the script works from any working directory.

**Root override — required, and this is why.** Accept a root-directory flag that scans a given directory instead of the repository's own. Without it, the integration tests have nowhere to point: the script would always scan the real tree, so any test of the failure paths would build the real baseline and dirty the repository while testing the rule that forbids it. Default to the repository root derived from the script's own location. Document in the script's header that the flag exists for tests and for inspecting a tree other than the repository's own, and that the default is the repository.

**Flag surface:** the list-only flag, the zero-match escape hatch, and the root override. Nothing else. Do not add a flag that skips validation — the escape hatch is specifically and only about an intentionally empty tree.

**Order of operations, exactly this order:**
1. **Depth rule first.** If any `platformio.ini` sits one level below a homework folder, set the failed state and print, in this order: the literal banner `DEPTH RULE VIOLATED`; a line stating that every homework must sit exactly one level below the homework directory; a two-to-three-line reason explaining that every shared-library path is project-relative so the symlinked relative dependency cannot resolve from a deeper folder; and one line per offending path.
2. **Id grammar second.** If any homework-directory name fails the frozen grammar, set the failed state and print the literal banner `MALFORMED HOMEWORK ID`, a line giving the expected pattern taken from the discovery module (not retyped here), and one line per offending folder.
3. **Exit 1 here, before anything else.** If either policy check failed, exit non-zero immediately — no zero-match logic and no build may run after a policy failure was found.
4. **Zero matches is a failure.** When the discovered list is empty: with the escape-hatch flag, print one line saying no homework projects were found and exit 0; without it, print three lines — that the sweep found zero homework projects, that a gate which built nothing must not exit 0, and that the escape-hatch flag should be passed only if an empty tree is genuinely expected — and exit 1.
5. **List-only exits here**, after validation and after the zero-match check, printing one id per line and exiting 0. This is the contract the CI matrix consumes in Phase 6, so it must never be able to emit an unvalidated or empty list.
6. **Resolve PlatformIO before the loop.** In order: an explicit environment-variable override, then the home-relative PlatformIO environment's binary if that file exists, then `pio` on the PATH confirmed by a probe whose spawn error is checked rather than ignored. If none resolves, print three lines — that PlatformIO Core was not found, that it can be installed, and an export line assigning the override variable to the home-relative binary path — then exit 1. Do not print a bare command name; print the absolute path and the export line, because the failure is otherwise unreadable.
7. **The loop.** For each discovered project, in sorted order, print a banner naming the resolved binary and the project, then spawn the build verb with an argument array: the verb, the project-directory flag, and the discovered relative directory — never a shell string, so nothing is word-split or re-interpreted, and no path can be read as a command. Set the child's working directory to the scanned root. Branch on the spawn error **separately** from the child's exit status: a spawn error prints that the binary could not be started plus the error message and sets the failed state; a non-zero status sets the failed state with no extra message. Never stop early — a failure on one project must not hide a failure on the next.
8. After the loop, if anything failed, print one line naming how many projects were checked and that at least one failed, then exit non-zero. Otherwise exit 0.

**Never** re-implement discovery, the grammar or the depth walk: import them. A second implementation is how the workspace file ends up listing fewer homeworks than the tree contains.
