<objective>
Record the resolved version set in `shared/pio/VERSIONS.md`, gate the fragment and that record with a pure-filesystem regression test, and update the two reader-facing documents so the console decision and the version record are reachable from the READMEs.

Purpose: this is the plan that makes criterion 3 true for someone who will never see this machine, and that converts the fragment's correctness from a one-time observation into a gate. Both traps it guards against are silent: a fragment that cannot be found is not an error, and a version record that quietly keeps a home-directory path would put a private machine detail into a public history. The regression gate is also the reason the environment assertion can be checked on every task commit rather than only during a build.

Explicitly out of scope for this plan, and deliberately not claimed: ROADMAP criterion 2 (the dated on-hardware acceptance run) and criterion 5's console half. Those belong to plan 02-03 and are reported UNMET if no board is attached. This plan discharges criterion 3, and the static halves of HW-01 and HW-04.

Output: `shared/pio/VERSIONS.md`; `tools/tests/env-baseline.test.mjs` and the fixture helper it needs; the updated baseline and repository READMEs; and a conditionally-aligned repository conventions file.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → public remote | Anything committed is world-readable forever, and the git history is an artifact the course instructor reads. |
| this machine's package cache → the version record | The listing tool's verbose form appends an absolute package path; copying it verbatim is one keystroke away and permanently exposes a private machine detail. |
| the regression suite → the platform binary | The suite is pure Node today; adding a process spawn would couple every task commit to a tool the repository cannot assume is resolvable. |
| a fixture tree → the tracked tree | The new test's fixture is the only thing this plan creates outside version control; its cleanup hook is what keeps temporary trees out of the working directory. |
| the conventions file → every reader | That file is GSD-generated and a regeneration can revert an edit; a criterion that leans on it would be quietly reversible by a tool the repository does not own. |
