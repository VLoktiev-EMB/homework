<objective>
Close code-review finding CR-02: make the tracked-source guard in `tools/tests/ignore-rules.test.mjs` fail closed for the root ignore file.

`isRepoOwnedIgnoreSource(source)` exists to answer one question — would a clone inherit the file `git check-ignore -v` named as the source? Its docstring states that tracked-ness is the whole distinction "so it is asked of git rather than inferred from the path". Line 59 short-circuits that question for the root ignore file by returning true on an identity comparison, so for `.gitignore` the answer is inferred from the path instead. The two guards below it (the absolute/`..` rejection and the basename check) already pass for `.gitignore`, and the `git ls-files --error-unmatch` call below them is the real work. Deleting the exemption routes the root file through the same path a nested one already takes.

The consequence is not cosmetic. Git resolves ignore rules from the working tree, not the index, so `git check-ignore -v` keeps reporting `.gitignore:<line>` for every protected path even after the file leaves the index — a fresh clone inheriting zero ignore rules still reads as green. The guard cannot see the one failure mode it exists to detect. Same fail-open class as sibling finding CR-01.

Purpose: before Phase 6 wires the repository's gates into hooks and CI, the ignore-contract guard must be able to fail. A guard that reports green on the exact input it was written to reject is worse than no guard, because it converts an absence of evidence into evidence of absence.
Output: one edited file, `tools/tests/ignore-rules.test.mjs`, with measured before/after evidence in both directions.

Explicitly out of scope, and deliberately left untouched: `.gitignore` itself; sibling findings CR-01 (`generate-workspace.mjs --check` fail-open), WR-12 (the comment-marker guard reads only the root ignore file), WR-13 (the nested project's generated `.vscode/*` rules appear in no `MUST_BE_IGNORED` entry) and WR-14 (`extensions.json` indentation); and the review ledger `.planning/phases/01-repository-skeleton-and-project-layout/01-REVIEW-DISPOSITION.md`, whose CR-02 disposition row is bookkeeping owned outside this plan.
</objective>
